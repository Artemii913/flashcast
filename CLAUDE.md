# FlashCast — контекст проекта

Этот файл Claude Code читает в начале каждой сессии. Здесь описано, что
такое проект, как он устроен сейчас и куда движется. Держи этот файл в
актуальном состоянии — это самый дешёвый способ получать качественную
помощь от AI.

---

## Что такое FlashCast

Веб-сервис, который автоматически собирает новости из российских
RSS-источников, формирует текст подкаста и озвучивает его через TTS.
Результат — MP3-файлы по категориям, которые можно слушать прямо на сайте.

- Сайт: https://artemii913.github.io/flashcast/
- Хостинг: GitHub Pages (статика, бэкенда нет)
- Слоган целевого продукта: «Включаю вместо радио»
- УТП (после встречи с экспертом 2026-04-23): персональный аудио-фильтр,
  который превращает проверенную экспертизу ведущих СМИ в лаконичные
  подкасты, освобождая пользователя от информационной тревожности.

## Текущая архитектура

### Фронтенд

- Один файл `index.html` (~1100 строк), CSS и JS встроены
- Шрифты: Montserrat (заголовки) + Source Sans 3 (текст), Google Fonts
- Цвета:
  - фон основной `#0a0a0f`, вторичный `#12121a`
  - акцент `#ff6b35` (оранжевый), `#ffcc00` (жёлтый, кнопка плеера)
  - текст `#ffffff` / `#a0a0b0`
- Адаптив: мобильный + десктоп
- Аналитика: Яндекс.Метрика, id `108251892`

### Что есть в интерфейсе

1. Шапка с логотипом и кнопкой «AI Подкаст»
2. QR-баннер для сбора отзывов (Google Forms, с МарсФеста)
3. Фильтры по категориям: Все / Технологии / Экономика / Спорт /
   Политика / Наука / Культура
4. Сетка карточек подкастов — карточки **загружаются из
   `data/podcasts.json`** через `fetch` (с fallback на захардкоженный
   массив на случай ошибки сети). См. PR #1.
5. Мини-плеер снизу
6. Fullscreen-плеер (выезжает снизу)
7. AI-чат — поп-ап справа снизу, **это не Claude API**, а простой
   JS-поиск по массиву `keywords` в данных карточки

### Структура карточки подкаста (в `data/podcasts.json`)

```js
{
  id: 0..6,
  title: "...",
  category: "Технологии" | "Экономика" | "Спорт" | "Политика" |
            "Наука" | "Культура" | "Все новости",
  date: "Сегодня",
  duration: "8:00".."25:00",  // статическая строка, не реальная длина
  image: "https://images.unsplash.com/...",
  audio: "data/podcast_tech.mp3",
  featured: true | false,
  keywords: ["...", "..."]    // для поиска в чате
}
```

### Бэкенд / автоматизация

Python-скрипты в `/scripts/`:

- `rss_parser.py` — парсит RSS из 7 категорий:
  - Новости: Коммерсантъ, Медуза
  - Технологии: Habr, 3DNews
  - Экономика: РБК, Ведомости
  - Политика: РИА Новости, Lenta
  - Наука: N+1
  - Культура: Lenta Культура, РИА Культура
  - Спорт: Sports.ru

  Берёт 2–4 новости с источника, дедуплицирует по заголовку, формирует
  скрипт **простой конкатенацией** — без AI-перефразирования.

- `tts_generator.py` — Edge TTS (Microsoft):
  - Голос по умолчанию: `ru-RU-DmitryNeural`
  - Альтернатива: `ru-RU-SvetlanaNeural`
  - Скорость +0%, громкость +0%

- `main.py` — запускает пайплайн `rss_parser → tts_generator` и сохраняет
  metadata.

### GitHub Actions (`.github/workflows/generate.yml`)

- Расписание: каждый день в 06:00 UTC
- Запуск вручную: `workflow_dispatch`
- Шаги: checkout → install deps → `rss_parser.py` → генерация MP3 →
  commit & push
- ⚠️ **Расхождение**: в CI используется `gTTS` (Google TTS), а локально
  `edge-tts`. Привести к единому при следующем рефакторинге (Задача 3).

### Зависимости

`feedparser`, `edge-tts`, `requests` (см. `requirements.txt`).

### Выходные файлы в `/data/`

- `podcast_tech.mp3`, `podcast_economy.mp3`, `podcast_sport.mp3`,
  `podcast_science.mp3`, `podcast_culture.mp3`, `podcast_all.mp3`,
  `podcast_news.mp3`
- `script_*.txt` — тексты подкастов (используются как материал для
  ретроспективных AI-брифингов на Этапе 3)
- `categories.json` — метаданные категорий
- `podcasts.json` — данные карточек для фронтенда (создан в PR #1)
- ⚠️ Устаревшие: `podcast.mp3`, `podcast_2026-01-15.mp3`, `script.txt` —
  можно удалить отдельным cleanup-PR

## Инсайты со встречи с экспертом (2026-04-23)

Эти 5 пунктов перевешивают многие технические задачи из исходного плана.
Перед предложением фич сверяйся с ними.

1. **Доверие к источникам — это главный продукт, а не агрегирование.**
   Пользователь готов «отключить» критическое мышление при
   прослушивании, только если он «включил» его при выборе СМИ. Lenta.ru,
   Коммерсантъ, NYT воспринимаются как «верифицированные», а РИА —
   нет. Список источников должен быть **видимым** и **управляемым**.

2. **Формат «целой мысли» (Whole Thought) важнее частоты.** Пользователи
   отписываются от лент с короткими алертами («для тревожников»),
   потому что обрывки фраз не несут законченную мысль. Наша конкатенация
   заголовков сейчас — это слабое место, не сила. Claude API нужен в
   первую очередь для рерайта в связный нарратив.

3. **Ретроспективные подкасты — killer feature.** «Хочу за полгода
   новости про МГУ» / «Прогресс Роскосмоса за год». Ни один новостной
   агрегатор такого не делает. У нас уже есть `script_*.txt` файлы за
   месяцы — основа для этого готова.

4. **Защита от «откуда новости?»** На презентациях обязательно
   спросят — нужен публичный блок «О наших источниках» с обоснованием
   (год основания, репутация, исследования). Аналогия эксперта:
   «мишленовская звезда для СМИ».

5. **Профильные подписки по темам.** «Банкир хочет про кофе → выбирает
   Коммерсантъ (котировки). Обычный человек хочет про кофе → выбирает
   Ленту (про здоровье)». Выбор источников зависит от темы, не глобален.

## Архетипы пользователей (из User Journey Report)

Используй для проверки фич: «закрывает ли это потребность хотя бы
одного архетипа?»

- **Консерватор** (Татьяна Борисовна) — лояльна Lenta.ru за «целую мысль»
  в каждой новости. Избегает фрагментированных лент.
- **Профи** (банкир / трейдер) — Коммерсантъ, Ведомости. Информация
  напрямую влияет на решения, ошибка стоит денег.
- **Искатель** — работает с тематическими архивами. «Что изменилось в
  высшем образовании за полгода». Не интересуется новостями дня.
- **Боевой настрой** — ищет жёсткий нефильтрованный контент («Пул №3»),
  острые политические тезисы, «не для розовых пони».

## Концепт мобильного интерфейса

Существует серия макетов мобильного приложения / PWA, описывающих
целевой UI. Используй их как ориентир при работе над Этапами 2 и 3.

### 5 экранов с нижней навигацией

1. **Поток** — главный экран. Сверху играющий трек (название + источник
   + прогресс + кнопки prev/play/next), ниже список «Далее в потоке» —
   карточки с типом контента (бейдж: музыка / подкаст / AI / новости) и
   длительностью. Это **autoplay-очередь**, не просто сетка.

2. **Каталог** — поиск + чипы-фильтры (Все / Новости / Подкасты /
   AI-брифинги / Музыка) + блок «Популярное». Глобальный поиск по
   всему контенту, не по одной категории.

3. **Ассистент** — **полноценный экран**, не виджет в углу. Пользователь
   формулирует запрос («что-нибудь про ИИ и немного музыки»), Claude
   собирает плейлист из разных типов контента и предлагает кнопки
   «Запустить» / «Изменить». Это качественно другой UX, чем нынешний
   JS-чат с поиском по `keywords`.

4. **Источники** — два блока:
   - Список «Мои источники» с тогглами для каждого из 8 встроенных СМИ
     (Коммерсантъ, Медуза, Habr, 3DNews, РБК, Ведомости, РИА, Lenta,
     N+1, Sports.ru). Состояние в `localStorage`. На фронте фильтруем
     карточки по выбранным источникам. Это решение из встречи с
     экспертом (инсайт #1: доверие к источникам).
   - «Соотношение в потоке» — горизонтальные слайдеры для категорий
     (Новости / Подкасты / Музыка). Управление пропорциями, не только
     включением. Откладывается до появления подкастов и музыки в потоке
     (Этап 2+).
   - ⏸ **Кнопка «Добавить свой RSS» — отложена**. На макете она есть,
     но реализация требует валидации фидов и серверной части. Делаем
     только когда появятся реальные пользователи и спрос на это.

5. **Профиль** — аватар, статус подписки (Free / Plus / Pro), 3 метрики
   (часы прослушивания / выпуски / источники), CTA на апгрейд, тогглы
   (уведомления, автозапуск утром, качество аудио), управление подпиской.

### 4 типа контента в потоке

UI явно разделяет контент по типу, с разными бейджами:

- **Новости** — текущая FlashCast-агрегация (RSS + TTS), бейдж `новости`.
- **Подкаст** — сторонние RSS-подкасты (пример из макета: «Это Норм»).
  Стримятся с сервера автора, не хостятся у нас.
- **AI** — генерируемые Claude брифинги по теме пользователя
  («AI-брифинг: рынки», «GPT-4o: что изменилось»).
- **Музыка** — royalty-free треки (в макете «Lofi Focus Mix»,
  «Focus Radio»), используются между блоками.

### Принятые решения по дизайну

- ✅ **Тема — пока тёмная** (`#0a0a0f` остаётся). Светлая из макетов
  будет добавлена позже как **переключатель в Профиле**, не вместо.
  Реализуется через CSS-переменные.
- ✅ **Макеты — целевой концепт**, не один из вариантов. При работе над
  Этапом 2 (нижняя навигация, autoplay-очередь) ориентироваться на
  структуру и иерархию из макетов, адаптируя цвета под тёмную тему.
- ⏸ **«Добавить свой RSS» отложено** до появления реальных пользователей
  и спроса. До этого момента «Источники» — это выбор из 8 встроенных
  СМИ через тогглы (см. Задачу 4 в плане).

## Обновлённый план развития

После встречи с экспертом приоритеты пересмотрены. NotebookLM
рекомендовал начать с миграции на FastAPI + VPS + Supabase — это
**преждевременно**: продуктовые инсайты эксперта можно реализовать на
текущем стэке (GitHub Pages + localStorage + опционально Cloudflare
Workers), без затрат на VPS и месяцев на инфраструктуру.

### Этап 1 — фундамент (текущий, 2–3 недели)

- ✅ **Задача 1** — динамическая загрузка карточек из `podcasts.json`
  (PR #1 смержен).
- ⬜ **Задача 2** — вынос CSS из `index.html` (требует явного согласования,
  правило 1 ниже).
- ⬜ **Задача 3** — унификация TTS под `edge-tts` (правка `generate.yml`
  и `requirements.txt`).
- ⬜ **Задача 4** — раздел «Источники» (новая, после встречи с экспертом).
  Пользователь видит все 8 СМИ, может галочками включить/выключить.
  Состояние в `localStorage`. Бэкенд не нужен — фильтрация на фронте.
- ⬜ **Задача 5** — блок «О наших источниках» / Trust Badge (новая).
  Краткое описание каждого СМИ, год основания, специализация. Закрывает
  риск с вопросом «откуда новости?» на презентациях.

### Этап 2 — качество контента (Claude API, 3–4 недели)

- ⬜ **Задача 6** — Claude API через прокси на Cloudflare Workers
  (бесплатно, ключ не на фронте). `rss_parser.py` отправляет собранные
  новости в Claude, получает связный текст в формате «целой мысли».
  **Это самое важное продуктовое улучшение** — отвечает на инсайт #2.
- ⬜ **Задача 7** — нижняя навигация (5 разделов) + autoplay-очередь.
  Косметика, делается после качества контента, а не до.

### Этап 3 — killer feature (4–6 недель)

- ⬜ **Задача 8** — ретроспективные AI-брифинги. Пользователь вводит
  тему, система ищет упоминания в `script_*.txt` за N дней, отдаёт всё
  в Claude, получает аналитический подкаст. Отвечает на инсайт #3.
- ⬜ **Задача 9** — пресеты профилей по архетипам (Консерватор / Профи /
  Искатель / Боевой настрой). Сохраняются в `localStorage`.

### Этап 4 — бэкенд (только когда упрёмся, 6+ месяцев)

Не делать раньше, чем видно, что пользователи возвращаются и
требуется хранить историю/подписки. Cloudflare Workers + Supabase или
аналог. VPS с FastAPI — крайний вариант, не первый.

### Монетизация (после Этапа 3)

- Free — реклама между блоками, базовые AI-брифинги
- Plus (299 ₽/мес) — без рекламы, офлайн, расширенные брифинги
- Pro (699 ₽/мес) — безлимит, API-доступ, white-label

## Важные правила работы с кодом

1. **Один файл `index.html`** — пока не сделана Задача 2, не создавай
   отдельные файлы CSS/JS без явного разрешения.
2. **GitHub Pages = только статика.** Никаких серверных вызовов,
   API-ключей на фронте, сессий. Для Claude API — только через прокси.
3. **Соблюдай цветовую схему и шрифты** (см. выше).
4. **MP3 в `/data/`** — обновляются GitHub Actions, не редактируй вручную.
5. **`podcasts.json`** — это файл для фронтенда (карточки). Его
   структура завязана на `index.html`. **`podcast.json`** в проекте нет.
6. **AI-чат пока не Claude API.** При подключении — обязательно через
   прокси, ключ нельзя на фронте.
7. **Расхождение TTS** между локальным окружением и CI — учитывай при
   изменении пайплайна, пока Задача 3 не сделана.
8. **Перед большой переделкой — делай отдельную ветку** через
   `git checkout -b feature/...` и коммить маленькими шагами.
9. **Перед предложением фичи — сверяйся с инсайтами эксперта.** Если
   фича не закрывает потребность ни одного архетипа и ни одного из 5
   инсайтов — не приоритет.
